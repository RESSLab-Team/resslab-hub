# Resslab Hub backend

FastAPI + SQLAlchemy 2.0 (async) + PostgreSQL 14. `make help` from this
folder lists every target. The dev server is `make dev` (or `make dev-backend`
at the root), on http://127.0.0.1:8000, docs at `/docs`. Alembic runs
`upgrade head` at every startup (`DATABASE_UPGRADE=false` to skip).

## Database migration

When a data dictionary changes in the data repo:

1. `make generate-model` regenerates the ORM models
   (`resslab_hub/models/database/*.py`) and the Pydantic schemas
   (`resslab_hub/models/api.py`). Both files are rewritten only between their
   `START_OF_GENERATED_CODE` / `END_OF_GENERATED_CODE` markers, the hand
   written parts around them stay. Read the diff.
2. `make database-revision name="what changed"` creates the Alembic revision.
   Check it, then `make database-upgrade` applies it.

The generator is `data/generate_model.py`, driven by `RESSLAB_DATA_DIR`
(default `../../resslab-hub-data`, a sibling of the repo).

```bash
make database-revision name="add foo column"   # new autogenerated revision
make database-upgrade                          # apply (also done at startup)
make database-downgrade                        # one revision back
```

## Upload data

Needs the data repo next to this one and the database up. See "Populate the
database" in the [root README](../README.md) for the clone and the Git LFS
note.

```bash
make upload-data          # everything, erases and refills every table, ~1 min
make upload-data-light    # one measurement file per series type, ~30 s
make upload-brace         # one component, see make help for the others
```

The uploader is a module of the package, so it also runs from the backend
image:

```bash
python -m resslab_hub.data.uploader all <path to resslab-hub-data>
python -m resslab_hub.data.uploader all <path> --series-limit 1   # the light variant
python -m resslab_hub.data.uploader brace <path>/braces/steel_braces.csv --debug
```

The first argument is a type from the `Type` enum in
`resslab_hub/data/uploader.py` (`all`, `all-braces`, `brace`,
`brace-displacement`, `dictionary`, `readme`, ...). The flow is drawn in
[resslab_hub/data/uploader.md](resslab_hub/data/uploader.md).

### Upload data to a deployed environment (dev, stage, prod)

Do not tunnel and upload from your laptop. Each environment has a suspended
CronJob `resslab-hub-upload-data-<env>` that does the same upload from inside
the cluster, next to the database. In the ArgoCD UI, open the environment's
application, find that CronJob and use the `create-job` action. It runs the
same backend image the environment serves, on the CSV data image built from
the `main` branch of the resslab-hub-data repo (`resslab-hub-data:main`, the
only branch, for every environment).

Two things to know:

- The job replaces the rows it owns, table by table. The site keeps serving
  during the run.
- The backend caches responses per process for one hour, so the new data can
  take up to an hour to show. Restart the backend pods from ArgoCD if you need
  it right away. The job writes to Postgres directly, so it cannot expire that
  cache itself ([dashboard-architecture.md](../docs/dashboard-architecture.md)).

Fallback if the cluster job is not an option (the data image is not built yet,
or you need to upload something that is not in the data repo): port-forward the
database and upload from your machine.

```bash
kubectl -n epfl-resslab-resslab-hub-dev port-forward svc/resslab-hub-db-dev 5433:5432
```

The local dev database already uses 5433 (see the root README), so pick
another local port if it is running, and set `POSTGRES_PORT` to match.

Set `secrets/.env` (at the **repo root**, not under `backend/`, the Makefile
loads `../secrets/.env`) with the creds from Infisical
(`/epfl-resslab/resslab-hub/db`, env slug `dev`, `staging` or `prod`):

```env
POSTGRES_HOST=localhost
POSTGRES_PORT=5433
POSTGRES_USER=<DB_USER>
POSTGRES_PASSWORD=<DB_PASSWORD>
API_PASSWORD=<any non-empty value>   # machine credential, see docs/auth.md
```

To send real sign-in mails instead of logging them, add the `SMTP_*` block
from `docs/auth.md`. Watch the quoting of `SMTP_USER`: double quotes turn the
backslash into a newline.

Then from `backend/`, run `make upload-data`. Note: it **erases** existing data in the tables it touches.

## Validate a component folder

With the backend running, `make validate-braces` (or any type listed by
`make validate-data`) tars that folder of the data repo and posts it to
`/validate` with the machine credential. Same check the data repo CI runs.
